# U3 Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a session feel live and conversational: an activity line and turn footer, Stop and urgency in the composer, speaker identity and reading tiers, per-tool renderers with folding, token streaming with subagent cards, and one shared composer with `/` commands, `@` completion and attachments, delivered as five stacked PRs on U2.

**Architecture:** The harness grows an ephemeral `LiveEvent` stream (never stored) and per-tool `meta` on tool results; the runtime keeps a small in-memory `LiveState` and publishes coalesced `live` frames, plus a stop hold, message cancel/restore, client-id dedupe, a command route and an upload route. The web app keeps U1's contract: `rows` derive only from persisted events through a stabilized pipeline (raw → stabilize → display passes → stabilize), every live, status, queue and clock change lands outside row identity, and the live text block shares its key and component with the row that replaces it.

**Tech Stack:** TypeScript, pnpm monorepo; Fastify + Drizzle/Postgres (`apps/server`, `packages/db`); `packages/harness` (Claude Code stream-json driver); `packages/shared` (Zod); React 19 + Vite + TanStack Router/Query (`apps/web`); Radix (`radix-ui@^1.8.1`), `cmdk@1.1.1` and `vaul@1.1.2` (already installed); react-markdown + Shiki; Vitest + Testing Library (jsdom); Biome.

**Spec:** `docs/superpowers/specs/2026-11-21-u3-chat-design.md` (decisions issue #103, follow-ups #104–#109). Read it with this plan; section numbers (§n) and acceptance numbers (A n) are the spec's. DESIGN.md amendment text is in spec §16 and lands in the PR §16 names.
