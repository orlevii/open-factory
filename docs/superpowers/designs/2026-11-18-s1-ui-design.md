## 1. Direction

### 1.1 Who, where, what

- **Who:** one developer or a small team running agent teammates on their own machine. They know terminals, editors, git and CI, and live in tools like GitHub, Linear and VS Code.
- **Where:** a browser tab left open next to the editor, for hours at a time, day and night. Later the main screens are watching a live session stream and triaging the inbox.
- **Mode:** Operate. The visitor is in a task. The interface should disappear into it, and brand shows only in precise details.

### 1.2 The world: "Pilot light"

A quiet, warm-graphite instrument panel with one live signal color. Picture a workshop control board at night: matte neutral surfaces, crisp type, and one small vermilion light that means "this is on, this is running, this has focus".

- **Neutrals carry everything.** A warm graphite scale (hue 70, chroma under 0.01). Warm, not blue-gray, so the tool feels like a workbench rather than a cloud console. Primary buttons are ink (near-black in light mode, near-white in dark mode), never colored.
- **One signal color: vermilion** `oklch(0.62 0.19 42)`. It is reserved for focus rings, the active nav marker, the wordmark's pilot light, text selection, the caret, and (from S3 on) the `working` status. It is never decoration and never a large fill. Because the color means "live", the S3+ session UI inherits a meaning, not just a color.
- **Status is never color alone.** Every status that S3+ shows pairs its color with a label or an icon. This matters because `errored` (crimson, hue 25) and `working` (vermilion, hue 42) are neighbors.
- **Type:** Geist Variable (already installed) for all UI text. **Geist Mono** for code, handles, slugs and keys, that is, for things that are literally identifiers. Mono is never used as a "technical" costume for labels.
- **Density:** compact but not cramped. Base UI text is 14px, controls are 32 to 36px tall, and the spacing is on a 4px grid. Later specs will put a lot on one screen (org tree, session timeline, task tables), so S1 sets the dense rhythm now.
- **Motion:** 150ms color and opacity transitions, and 200ms for the sidebar. There is one authored moment: the pilot light breathes while the app is loading (§5.1), and the same pulse later marks a `working` agent. Everything respects `prefers-reduced-motion`.
- **Dark mode** follows the system only, and is an equal citizen rather than an inverted afterthought. Many users will be in dark mode at night. The dark sidebar is darker than the content area (a recessed rail). The light sidebar is a slightly deeper warm neutral than the content area.

### 1.3 Copy voice

Plain, short, specific. It reads like a calm senior engineer.

- Sentence case everywhere ("Create your account", not "Create Your Account").
- No exclamation marks, no "Oops", no emoji, no "Welcome aboard". Address the user as "you".
- Errors name the problem and the way out: "Can't reach the server. Check that it's running, then try again."
- Buttons name their action: "Sign in", "Sign up", "Reload".
- Empty states use the spec's exact one-liners, and nothing more in S1.
- The product nouns (Inbox, Agents, Tasks, Templates, Schedules, Settings) are capitalized only as nav labels and page titles. In running text they are lowercase ("Nothing in your inbox.").

### 1.4 Things this design refuses

Eyebrow labels above headings (the current `AuthCard` has one; see §4.1). Gradient text. Glass. Shadows as decoration: cards are flat with a 1px border. Colored left-border callouts. Centered hero empty states with illustrations. Spinners in the middle of content. Modals. Toasts (also banned by the spec).

### 2.3 Spacing, radius, elevation, motion

- **Spacing:** 4px grid. Page gutter: `px-4` on mobile, `md:px-6` on desktop. Page content block: `py-6`. Space between stacked sections: `gap-6`. Form field stack: `gap-4`. Label-to-input gap: `gap-1.5`.
- **Radius:** `--radius: 0.5rem`. Inputs and buttons use `rounded-md` (≈6.4px), panels `rounded-lg` (8px), the wordmark tile `rounded-[5px]`.
- **Elevation:** flat. Panels have a 1px `border` and no shadow. Only overlays (dropdown, sheet) cast a shadow, and they use shadcn's defaults.
- **Motion tokens:** `duration-150 ease-out` for hover, color and opacity; the sidebar keeps shadcn's 200ms. Ease-out curve: `cubic-bezier(0.22, 1, 0.36, 1)`.

### 2.4 Reserved status vocabulary (for S3+, documented now)

The status vocabulary is a dot of 8px (`size-2 rounded-full`) followed by a lowercase label. For example, `working` is a vermilion dot with the `pilot` pulse from §5.1, `idle` is green, `queued` is blue, `hibernated` is gray, `rate-limited` is amber, `errored` is crimson, and `terminated` is a hollow gray ring. S1 renders none of this. It is listed so that S3 doesn't invent a second vocabulary.

### 4.2 Fields (`FormField`)

|                        | Sign-in                       | Sign-up                                |
| ---------------------- | ----------------------------- | -------------------------------------- |
| Fields                 | Email, Password               | Name, Handle, Email, Password          |
| Autofocus              | Email                         | Name                                   |
| Submit label / pending | "Sign in" / "Signing in…"     | "Sign up" / "Signing up…"              |
| h1                     | "Sign in"                     | "Create your account"                  |
| Footer                 | "No account yet? **Sign up**" | "Already have an account? **Sign in**" |

The submit labels stay "Sign in" and "Sign up", which is what the existing tests query.

- **Label:** shadcn `Label`, 13px/500, `gap-1.5` above the input. Labels are always visible; placeholders never replace them. Placeholders are optional; if one is used it must be an example (`you@example.com`), never an instruction.
- **Input:** shadcn `Input` at `h-9`, with a 1px `--input` border and a `--card` background. Focus shows the vermilion ring. Invalid state (`aria-invalid`) uses a `--destructive` border and the destructive ring; shadcn's `aria-invalid:` styles already do this.
- **Handle input:** an `@` adornment drawn inside the left edge of the field (`pointer-events-none absolute left-3 text-muted-foreground font-mono`), input `pl-7 font-mono`, `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}`, `maxLength={32}`. Keep the existing lowercasing on change. The `@` is visual only: the submitted value has no `@`. Use a wrapper `div` with `relative`, or shadcn `input-group` if the registry has it. Don't add a new dependency for this.
- **Help text** (new optional `help` prop on `FormField`):
  - Handle: "How agents mention you, like @alice. Lowercase letters, numbers and hyphens."
  - Password (sign-up only): "At least 8 characters."
- **Help vs. error:** when a field has an error, the error **replaces** the help text in the same slot, and `aria-describedby` points only at the error id. Without an error it points at the help id. The existing tests assert the exact accessible description of an errored field, so this keeps them green.
- **Error text:** `text-[13px] text-destructive`, with an optional 14px `CircleAlert` lucide icon (`aria-hidden`) and a `gap-1.5`. Message copy comes from `mapAuthError` (plan Task 8 step 2), unchanged:
  - `HANDLE_TAKEN` → handle: "That handle is already taken."
  - `VALIDATION_ERROR` → handle: the server's message
  - `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL` → email: "An account with this email already exists."
  - `PASSWORD_TOO_SHORT` → password: "Password must be at least 8 characters."
  - `INVALID_EMAIL_OR_PASSWORD` → form: "Wrong email or password."
  - anything else → form: the server message, or "Something went wrong. Try again."
- **Client validation copy:** the shared Zod messages are shown as they are. If they read like code ("String must contain at least 2 character(s)"), map the handle issues in the form to: "Use 2–32 characters.", "Use lowercase letters, numbers and inner hyphens.", "That handle is reserved." This is optional polish; don't change the shared schema just for wording.

### 4.3 Behavior and states

- **Validation timing:** on submit. After the first failed submit, editing a field clears that field's error. There's no live re-validation as you type.
- **Focus:** after a failed submit, move focus to the first invalid field. For a form-level error, focus stays on the button and the alert is announced.
- **Submitting:** the button is disabled, shows a 14px `Loader2` with `animate-spin` before the pending label, and keeps its width. Inputs stay enabled (no layout jump). This is the only spinner in S1, and it's inline in a control, not in the middle of content.
- **Form error:** a `<p role="alert">` directly **above** the submit button, `text-[13px] text-destructive`, with a `CircleAlert` icon.
- **Server unreachable** (new mapping, see §9.3): "Can't reach the server. Check that it's running, then try again."
- **Signed-in user visits /sign-in:** redirected to `/` by the existing guard. No flash: the pending UI from §5.1 covers the gap.
- **Password managers:** `autoComplete` values as currently implemented (`email`, `current-password` / `new-password`, `name`, `username` on the handle).

### 4.4 Responsive and accessibility

- Below 360px the column is full width inside a 16px gutter. Nothing else changes.
- Tab order: fields, then the submit button, then the footer link. Enter submits.
- `<main>` landmark, a single `h1`, and `noValidate` on the form (we render our own errors).
- Contrast: help and error text meet 4.5:1 on `--background` in both themes (§2.1).

## 5. Signed-in shell (`_app` layout)

### 5.1 Pending and loading (route guard, first load)

While `beforeLoad` resolves the session, the router shows a pending screen. Add to `createAppRouter`: `defaultPendingComponent: AppPending`, `defaultPendingMs: 400`, `defaultPendingMinMs: 300`.

`AppPending` is a full-viewport `bg-background` with only the `Mark` centered, at 28px, with its pilot dot breathing. This is the product's single authored motion moment.

```css
@keyframes pilot {
  0%,
  100% {
    opacity: 1;
  }
  50% {
    opacity: 0.35;
  }
}
.is-loading .pilot {
  animation: pilot 1.6s cubic-bezier(0.22, 1, 0.36, 1) infinite;
}
```

- The container carries the class `is-loading`, which is what turns the pulse on. It also has `role="status"`, `aria-live="polite"`, and an sr-only "Loading…".
- Fast loads (under 400ms) show nothing at all, so there is no flash.
- Under reduced motion the dot is static.
- Later, S3 reuses `.pilot` for the `working` status dot.

Desktop collapses to a 3rem icon rail through the header trigger or shadcn's built-in Cmd/Ctrl+B. The state persists in shadcn's `sidebar_state` cookie, which is a convenience cookie and not auth.
- **SidebarHeader:** `<Link to="/">` wrapping `<Wordmark/>`, `h-12 px-3`, aligned with the page header's bottom border. In icon mode only the `Mark` shows.
- **Nav** (unchanged items and icons; they're already good lucide choices: Inbox, Bot, ListTodo, LayoutTemplate, CalendarClock, Settings):
  - Rows are `h-8 text-sm` with 16px icons and `gap-2.5`, and `tooltip={item.label}` on `SidebarMenuButton` for icon mode.
  - **Active:** `--sidebar-accent` background, `--sidebar-accent-foreground` text, `font-medium`, plus a **2px vermilion marker**. Draw the marker as `before:absolute before:left-0 before:inset-y-1.5 before:w-0.5 before:rounded-full before:bg-signal`, inside the row, not as a border on the item. Set `aria-current="page"` on the active link.
  - **Active matching:** `pathname === item.to || pathname.startsWith(item.to + "/")`, so later detail routes (`/agents/foo`) keep their parent highlighted. `/` highlights nothing; the wordmark is the way home.
  - **Hover:** `--sidebar-accent` at full strength, 150ms. **Focus:** the vermilion ring.
- **SidebarFooter:** the user menu button (`size="lg"`).
  - The button shows the name (14px/500) and `@handle` (12px, `font-mono`, muted), both truncated, with `ChevronsUpDown`.
  - Drop the avatar: there are no avatars in S1, and an initial-in-a-circle adds nothing.
  - The dropdown (`side="top"`, `align="start"`, `w-56`) starts with a `DropdownMenuLabel` in two lines (name, then `@handle` in mono), then a separator, then "Sign out" with the `LogOut` icon.
  - Sign-out is one click with no confirmation (it's cheap to undo).
  - **Icon mode:** the footer shows only a 32px rounded square holding the handle's first letter (mono, muted background), which opens the same menu. This is the one exception to "no avatar": it's a necessity in icon mode.
- **Skip link:** the first focusable element in the layout is `<a href="#content" className="sr-only focus:not-sr-only focus:absolute focus:left-3 focus:top-3 focus:z-50 …">Skip to content</a>`. `<main id="content" tabIndex={-1}>`.

### 5.3 Page header (new `PageHeader` component)

Today `_app.tsx` has a mobile-only header with the trigger, and each screen renders its own `h1`. Replace both with one shared header that every screen renders:

```tsx
// components/page-header.tsx
export function PageHeader({ title, actions }: { title: string; actions?: ReactNode }) {
  return (
    <header className="flex h-12 shrink-0 items-center gap-2 border-b px-4 md:px-6">
      <SidebarTrigger className="-ml-1.5" />
      <h1 className="text-[15px] leading-5 font-semibold">{title}</h1>
      {actions && <div className="ml-auto flex items-center gap-2">{actions}</div>}
    </header>
  );
}
```

- The trigger is visible at every width: on desktop it collapses the sidebar to icons, on mobile it opens the sheet.
- `actions` is empty in S1. It's the seam for S4's "New agent", S8's "New task", and so on.
- The `_app` layout's `<main>` becomes `flex min-w-0 flex-1 flex-col`, without padding. Each screen renders `<PageHeader/>`, then `<div className="px-4 py-6 md:px-6">…</div>`.

### 5.4 Mobile (< 768px; shadcn's `useIsMobile` breakpoint)

- The sidebar becomes shadcn's off-canvas `Sheet` (built in), opened from the page header trigger. Choosing a nav item closes the sheet: call `setOpenMobile(false)` in the item's `onClick`. The shadcn sidebar does not do this by itself.
- In the sheet, nav rows are `h-9` for easier touch targets.
- The page header stays at `h-12` with the trigger and title.
- Dashboard panels stack in one column.

### 5.5 Disconnected (WebSocket) state

S1 has no live data yet, so connection status is shown **only when something is wrong**. There's no permanent "Live" badge.

- **Trigger:** the WS client reports `connecting` or `closed` for **more than 3 seconds** after it has been open at least once, or more than 5 seconds on the very first connect. Short blips don't show anything.
- **UI:** a 32px strip directly under the page header, full content width, `bg-muted text-muted-foreground text-[13px] px-4 md:px-6`. It shows a 6px `--warning` dot and the text "Connection lost. Reconnecting…". It isn't dismissable, and it disappears as soon as the socket is open again. Nothing toast-like.
- `role="status"` and `aria-live="polite"`.
- When the session turns out to be gone, the existing `onUnauthenticated` path routes to `/sign-in` and the strip never matters.
- This needs a small addition to `connectWs`; see §9.4.

### 5.6 Route error and not-found states

- **`defaultErrorComponent`** (router), rendered inside the content area when it's under `_app`:
  - h2 "Something went wrong."
  - muted 13px text: "This page hit an error it couldn't recover from."
  - a `<pre>` (mono 12px, `bg-code border border-code-border rounded-md p-3 max-h-40 overflow-auto`) with `error.message`
  - a row with `Button` "Reload" (default, ink; `location.reload()`) and `Button variant="ghost"` "Go to Home" (`Link to="/"`)
- **`defaultNotFoundComponent`:** the same composition, with "Page not found." and the muted line "Check the address, or go back to Home." (no `<pre>`).
- Both are left-aligned at the top of the content area, like the empty states. Nothing is centered or illustrated.
- _As implemented:_ the error state's primary button is "Retry" (`router.invalidate()`: reloads the route data and resets the boundary) instead of "Reload"; the not-found state has only "Go to Home".

### 7.4 Mermaid in dark mode (CSS-only constraint)

Mermaid bakes concrete colors into its SVG when it renders, so it can't follow CSS variables, and switching its theme in JS would break the spec's CSS-only rule. The design therefore renders diagrams with `theme: "neutral"` on a light paper card (`--diagram-bg`) in **both** modes. In dark mode a diagram reads as a printed sheet on the desk. That's deliberate, consistent and legible. Add `theme: "neutral"` to the `mermaid.initialize` call, next to `securityLevel: "strict"`.

A true dark diagram theme is deferred. It would need JS (render per scheme), so it isn't S1 work.

- Landmarks: `nav[aria-label="Main"]` (exists), `main#content`, page `h1` in `PageHeader`, dashboard panels as `section` with h2s.
